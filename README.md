# megademo - "Megablast" (Orange, Dec 1996)
Port status: **started, 16 of 17 effects ported** (fx02 "moire plasma", fx03 "moire + logo", fx08 "star logo", fx10 "megablast logo" and fx07 "voronoi wire" = bit-exact vs the oracle, see below; fx05 "cube grid" and fx09 "flower blob" = bit-exact; fx00 "helicopter", fx01 "light rays" and fx04 "light lines" = bit-exact; fx13 "crowd - Dali" = 1 pixel off; fx11 "blue ring", fx12 "checker tunnel", fx14 "bar photo + logo", fx15 "blue sphere", fx16 "green blob" = bit-exact); only fx06 (vortex) shows a placeholder in the player. Own `.git` in this folder (not used for commits); originals untouched.
Files: DEMO.EXE (PMODE/W 1.20 + Watcom C + MIDAS-like lib), DATA.DAT (4 MB blob, 24 assets by offset table), MUSTAKS.S3M (music, 285 s used), PLASTI3D.PCX (texture).
Run the player: `cd web && python3 -m http.server 8000` (shell copied from `../stv/web`: pause, seek, effect list, 4:3). Test: `node tools/uitest.mjs` (headless Chrome: play/pause/seek, ported effect renders, seek determinism; passes).
## What is bit-exact vs not
- **fx00 (helicopter, stage 1, orders 0-2)**: `web/fx/fx00.js`, **1505 oracle frames, 0 differing pixels, 0 differing palette bytes** (`node tools/fx00check.mjs oracle.bin`, oracle `re/oracle_fx00.npz` -> `tools/oracle2bin.py`; assets `tools/export_fx00.py` -> `web/assets/fx00.bin`, 2.8 MB: asset 4 is simply 240 RLE frames of 160x80 shown 2x with blending, a new one every 6.5 ticks, palette fade-in). Pure function of the tick count (all state has closed forms), seek exact. The tick count from music time (n = floor(t*70.086)+1) is a model as for the other stages.
- **fx01 (light rays, stage 2, orders 3-5)**: `web/fx/fx01.js`, **832 oracle frames, 0 differing pixels, 0 differing palette bytes** (`node tools/fx01check.mjs oracle.bin`, oracle `re/oracle_fx01.npz`, assets `tools/export_fx01.py`). Same ray/blur family as fx04, plus a mask picture (asset 2) and a ray-length budget. Feedback: replay from the stage start (<= ~830 ticks). The oracle's stage ends after 832 ticks = 11.87 s after order 3 row 0, i.e. the end flag (fade reaching 0 after order 5 starts) confirms the fx02 start (5,12) to ~0.1 s (it is still the tabulated row, not derived). The player feeds the per-tick order from libopenmpt (the checker uses the oracle's order).
- **fx05 (cube grid, stage 6, orders 0x0e-0x0f)**: `web/fx/fx05.js`, **762 oracle frames, 0 differing pixels, 0 differing palette bytes** (`node tools/fx05check.mjs oracle.bin`, oracle `re/oracle_fx05.npz` -> `tools/oracle2bin.py`; assets `tools/export_fx05.py` -> `web/assets/fx05.bin`). Integer-only (3 rotations, perspective idiv, line walker, dword blur). Feedback effect: seek = replay from the stage start (<= ~780 ticks). The beat flash (palette x1.25 on S3M rows 0,6,0x12,0x1c,0x2a,0x32,0x3e) is driven by the row read at each update: the checker replays the oracle's rows, the player uses libopenmpt rows at t0 + k/70.086 (same model-n caveat as the others).
- **fx09 (flower blob, stage 10, orders 0x18-0x1b)**: `web/fx/fx09.js`, **1533 oracle frames, 0 differing pixels, 0 differing palette bytes** (`node tools/fx09check.mjs oracle.bin`, oracle `re/oracle_fx09.npz`, assets `tools/export_fx09.py` -> `web/assets/fx09.bin`). Integer-only: 1024 points on a sum-of-8-sines radius spin, 16x16 saturating splat, dword blur, background add. Feedback effect (replay from the stage start, <= ~1550 ticks), pure function of n otherwise (no row/order dependence). Same model-n caveat.
- **fx04 (light lines, stage 5, orders 0x0b-0x0d)**: `web/fx/fx04.js`, **1149 oracle frames, 0 differing pixels, 0 differing palette bytes** (`node tools/fx04check.mjs oracle.bin`, assets `tools/export_fx04.py`). Feedback effect (ray/blur buffer): seek = replay from the stage start (<= ~1150 ticks). Same model-n caveat.
- **fx12 (checker tunnel, stage 13, orders 0x24-0x25)**: `web/fx/fx12.js`, **765 oracle frames, 0 differing pixels, 0 differing palette bytes** (`node tools/fx12check.mjs re/oracle_fx12.bin`; oracle from `re/fx_oracle.py`, see `re/NOTES.md`). Feedback effect (stateful, seek = replay from the stage start). The checker replays the oracle's per-render orders; in the player the order comes from the libopenmpt timeline.
- **fx14 (bar photo + megablast logo, stage 15, orders 0x2a-0x2d)**: `web/fx/fx14.js`, **1538 oracle frames, 0 differing pixels, 0 differing palette bytes** (`node tools/fx14check.mjs`, see `re/NOTES.md`). Feedback effect (seek = replay from the stage start). The stage only writes rows 8..191; rows 0-7/192-199 show fx13's last frame (the oracle's last fx13 render was n=1533, the player uses the ideal last tick). UNRESOLVED: the real tick count per render (model n = floor((t-T0)*70.086)+1).
- **fx11 / fx15 / fx16 (stages 12, 16, 17: blue ring, blue sphere, green blob; one shared engine, render 0x2217d, updates 0x2243d / 0x224e9)**: `web/fx/engine2217.js` (+ `fx11.js`, `fx15.js`, `fx16.js`), **0 differing pixels, 0 differing palette bytes** over 1536 / 767 / 1100 oracle frames (`node tools/fx11check.mjs oracle.bin [variant] [x]`, oracles in `re/oracle_fx11/15/16.npz`, convert with `tools/oracle2bin.py`; assets `tools/export_fx11.py` -> `web/assets/fx11.bin`). Feedback effects (seek = replay from the stage start). Cross-stage state is part of the definition: stage 16 starts with stage 12's final wave phases (stage 12 ran 1540 ticks in the oracle; the init only clears the planes), stage 17 keeps stage 16's planes and phases (stage 16 = 770 ticks, a render every 7th as in the K=7 oracle run) and only resets the steps and swaps palette G/B. Caveats: (1) the fx16 oracle is checked with that K=7 history of stage 16, not with the K=1 fx15 oracle (a different run); (2) the real tick count per render is timing dependent, the player uses n = floor((t-T0)*70.086)+1 as for fx12/fx14; (3) stage 17's start state in the player is the oracle's (770 ticks), not derived from the music time.
- **Timeline**: S3M order/row -> seconds from libopenmpt (`tools/mk_timeline_openmpt.py`); the own S3M walker that drove the Unicorn clock agrees with it on all 3435 rows with max 0.34 s difference (0.1 %). Stage start rows come from the 10 fps golden run: exact (row 0 of the order) for all but fx02->fx03 (5,12), only +-0.1 s.
- **fx13 (crowd - Dali, stage 14)**: ported from the disassembly (`web/fx/fx13.js`), diffed against a per-frame oracle of the original under Unicorn (`re/fx_oracle.py`, `tools/fx13check.mjs`): 1538 frames, palette identical, **161 differing pixels, all the same pixel (314,193), in frames with animation frame 6**: the original reads past the end of its own frame buffer there (uninitialised/dynamic memory), my port reads 0. Not fully bit-exact, cause not resolved (see `re/NOTES.md`). Seek: pure function of the tick count, exact. The tick count from music time (n = floor((t-t_start)*70.086)+1) is a model: the original's own count depends on real timing.
- **fx02/03/08/10 (moire family)**: shared engine `web/fx/moire.js` (assets `tools/export_moire.py` -> `web/assets/moire.bin`), checked with `node tools/moirecheck.mjs STAGE oracle.bin`: 1478/765/765/1538 oracle frames, **0 differing pixels, 0 differing palette bytes**. The stages are chained (corner phases and counters persist), so the player starts each stage from a state replayed from the previous one; the tick counts of the previous stages (`END` in moire.js: 1477, 770, 770) are the oracle's real counts, which depend on the original's timing, so the start phase is a fit to that run (without them stages 8/10 were off). Verified at frames 1 and 300 of each stage.
- **fx07 (voronoi wire, stage 8)**: `web/fx/fx07.js`, `node tools/fx07check.mjs oracle.bin`: 767 frames, **0 differing pixels on rows 1..198 and 0 palette bytes**; rows 0 and 199 are not compared and are drawn black (not verified). The oracle's first frame includes a catch-up of fx06's ticks (fx06 has no update loop), modelled by K0 in the player. Tick count from music time is a model, as for fx13.
- **Not ported: fx06 (vortex, stage 7; x87 render 0x23288, init 0x231c4)** shows the placeholder. Asset 5 (128000 B) is still undecoded.
- Golden frames `re/golden/` (K=7, 10 fps) are the original code's own output on a fake clock.
See `re/NOTES.md`.

- fx14 player: rows 0-7 / 192-199 are drawn black (`KEEP_FX13_BORDER = false` in `web/fx/fx14.js`); the emulated original shows fx13's stale last frame there under fx14's palette, i.e. green bands. `tools/fx14check.mjs` is unaffected (it does not use `render`).
