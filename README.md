# megademo - "Megablast" (Orange, Dec 1996)
Port status: **started, 6 of 17 effects ported** (fx13 "crowd - Dali" = 1 pixel off; fx11 "blue ring", fx12 "checker tunnel", fx14 "bar photo + logo", fx15 "blue sphere", fx16 "green blob" = bit-exact); the other 11 show a placeholder in the player. Own `.git` in this folder (not used for commits); originals untouched.
Files: DEMO.EXE (PMODE/W 1.20 + Watcom C + MIDAS-like lib), DATA.DAT (4 MB blob, 24 assets by offset table), MUSTAKS.S3M (music, 285 s used), PLASTI3D.PCX (texture).
Run the player: `cd web && python3 -m http.server 8000` (shell copied from `../stv/web`: pause, seek, effect list, 4:3). Test: `node tools/uitest.mjs` (headless Chrome: play/pause/seek, ported effect renders, seek determinism; passes).
## What is bit-exact vs not
- **fx12 (checker tunnel, stage 13, orders 0x24-0x25)**: `web/fx/fx12.js`, **765 oracle frames, 0 differing pixels, 0 differing palette bytes** (`node tools/fx12check.mjs re/oracle_fx12.bin`; oracle from `re/fx_oracle.py`, see `re/NOTES.md`). Feedback effect (stateful, seek = replay from the stage start). The checker replays the oracle's per-render orders; in the player the order comes from the libopenmpt timeline.
- **fx14 (bar photo + megablast logo, stage 15, orders 0x2a-0x2d)**: `web/fx/fx14.js`, **1538 oracle frames, 0 differing pixels, 0 differing palette bytes** (`node tools/fx14check.mjs`, see `re/NOTES.md`). Feedback effect (seek = replay from the stage start). The stage only writes rows 8..191; rows 0-7/192-199 show fx13's last frame (the oracle's last fx13 render was n=1533, the player uses the ideal last tick). UNRESOLVED: the real tick count per render (model n = floor((t-T0)*70.086)+1).
- **fx11 / fx15 / fx16 (stages 12, 16, 17: blue ring, blue sphere, green blob; one shared engine, render 0x2217d, updates 0x2243d / 0x224e9)**: `web/fx/engine2217.js` (+ `fx11.js`, `fx15.js`, `fx16.js`), **0 differing pixels, 0 differing palette bytes** over 1536 / 767 / 1100 oracle frames (`node tools/fx11check.mjs oracle.bin [variant] [x]`, oracles in `re/oracle_fx11/15/16.npz`, convert with `tools/oracle2bin.py`; assets `tools/export_fx11.py` -> `web/assets/fx11.bin`). Feedback effects (seek = replay from the stage start). Cross-stage state is part of the definition: stage 16 starts with stage 12's final wave phases (stage 12 ran 1540 ticks in the oracle; the init only clears the planes), stage 17 keeps stage 16's planes and phases (stage 16 = 770 ticks, a render every 7th as in the K=7 oracle run) and only resets the steps and swaps palette G/B. Caveats: (1) the fx16 oracle is checked with that K=7 history of stage 16, not with the K=1 fx15 oracle (a different run); (2) the real tick count per render is timing dependent, the player uses n = floor((t-T0)*70.086)+1 as for fx12/fx14; (3) stage 17's start state in the player is the oracle's (770 ticks), not derived from the music time.
- **Timeline**: S3M order/row -> seconds from libopenmpt (`tools/mk_timeline_openmpt.py`); the own S3M walker that drove the Unicorn clock agrees with it on all 3435 rows with max 0.34 s difference (0.1 %). Stage start rows come from the 10 fps golden run: exact (row 0 of the order) for all but fx02->fx03 (5,12), only +-0.1 s.
- **fx13 (crowd - Dali, stage 14)**: ported from the disassembly (`web/fx/fx13.js`), diffed against a per-frame oracle of the original under Unicorn (`re/fx_oracle.py`, `tools/fx13check.mjs`): 1538 frames, palette identical, **161 differing pixels, all the same pixel (314,193), in frames with animation frame 6**: the original reads past the end of its own frame buffer there (uninitialised/dynamic memory), my port reads 0. Not fully bit-exact, cause not resolved (see `re/NOTES.md`). Seek: pure function of the tick count, exact. The tick count from music time (n = floor((t-t_start)*70.086)+1) is a model: the original's own count depends on real timing.
- Other 11 stages: only identified visually (`re/NOTES.md` table), update/render function addresses known, not ported. Helicopter (asset 4, 2.8 MB) and assets 5 are still undecoded.
- Golden frames `re/golden/` (K=7, 10 fps) are the original code's own output on a fake clock.
See `re/NOTES.md`.
